# Sprint 11 Gemini Live transport findings

The official Google Gemini Live WebSocket API reference states that a session can exchange text, audio, and video and defines `realtimeInput` as real-time audio, video, or text input. The official Live API capabilities guide states that `send_client_content` is only supported for seeding initial context history and that text updates during an active conversation must use `send_realtime_input` instead.

For this repository’s raw WebSocket transport, the corresponding client-to-server shape is the existing `sendControl()` path’s `realtimeInput: { text: ... }`. Sprint 11 context notes must therefore use a dedicated sanitized `realtimeInput.text` message through the transport, not `clientContent`/`send_client_content`. No Gemini 3.1 emotion field will be invented; prosody labels remain local application context.

Sources:
- https://ai.google.dev/api/live — Live API WebSockets API reference
- https://ai.google.dev/gemini-api/docs/live-api/capabilities — Live API capabilities guide
