## 2025-05-19 - Fast tuple prefix checking and single-pass list cleaning in memory service
**Learning:** `_strip_instruction_prefixes` was allocating a new list of prefix strings and a generator expression on every single line of message text, while `_clean_memory_list` ran `_redact_memory_sensitive` and `sanitize_text` on every list item before passing it to `_unique_clean`, which ran the exact same 5 regexes and PII sanitization a second time. Using native C `str.startswith` with a module-level tuple of prefixes reduced line filtering from ~1.05s to ~0.22s (~4.7x faster), while delegating directly to `_unique_clean(..., max_chars=220)` reduced payload cleaning time from ~2.11s to ~1.41s (~33% faster).
**Action:** Use module-level tuples for `str.startswith()` prefix checks to leverage Python's native C tuple prefix matching, and avoid nested data-cleaning functions running redundant regex/redaction passes on the same items.

## 2025-05-18 - Precompute RAG unit search terms for linear-time retrieval
**Learning:** RAG unit retrieval scoring was re-tokenizing, lowercasing, sanitizing strings, and re-building candidate sets on every single query for all GroundingUnits in memory. Precomputing search terms (`PreparedSearchTerm` dataclass with tokens and lowercased string), category/technique lowercased strings, candidate sets, and normalization factors during `reload()` reduced 100 retrieval iterations from ~0.93s to ~0.08s (~11.6x faster retrieval / ~15x faster scoring).
**Action:** When working with static or loaded corpus structures in python memory, precompute search tokens, lowercased keys, candidate lookup sets, and normalization factors once at load time rather than inside query execution loops.
